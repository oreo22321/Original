# 代行Bot（BDFD）

代行サービスのサーバー向けのBotです。**注文チケット・実績投稿**と**発言代行**ができます。
ボタンとフォームの処理を除き、すべてのコマンドが **`/`（スラッシュ）と `!`（プレフィックス）の両方**で動きます。

- 無料版で使える関数だけを使用（プレミアム不要）
- 2026年7月時点の公式Wikiで関数の構文を確認済み（BDScript 2）
- iPhone（Safari ＋ BDFDアプリ）だけで設定できます

## 注文の流れ

1. 管理者が `/setup` で、スタッフロール・チケット用カテゴリ・実績チャンネルを設定する
2. 管理者が注文用チャンネルで `/panel` を実行し、「注文する」「料金表」ボタンを置く
3. お客さんが **注文する** を押してフォームを送信（または `/order`・`!order`）
4. 専用チャンネル `order-番号` が作られる（見えるのは本人とスタッフだけ）
5. スタッフが `/claim` で担当 → 作業 → `/done` で完了（実績チャンネルに自動投稿）
6. お客さんが `/review` で ⭐1〜5 の評価（実績チャンネルに投稿）
7. `/close` でチャンネルを削除

## コマンド

| カテゴリ | コマンド | ファイル |
|---|---|---|
| ⚙️ 初期設定 | `/help` `/setup` `/panel` | [commands/01-setup.md](commands/01-setup.md) |
| 🛒 注文受付 | `/order` `/menu` ＋ボタン・フォームの処理3つ | [commands/02-order.md](commands/02-order.md) |
| 🧑‍💼 スタッフ用 | `/claim` `/done` `/close` | [commands/03-staff.md](commands/03-staff.md) |
| ⭐ 実績・レビュー | `/review` `/stats` | [commands/04-review.md](commands/04-review.md) |
| 📢 発言代行 | `/say` `/embed` `/send` | [commands/05-say.md](commands/05-say.md) |

BDFD上のコマンドは合計16個です。

### `!` で使うときの書き方
文章を複数入れるコマンドは **`|`（縦線）で区切ります**。

```
!setup @スタッフ 123456789012345678 #実績
!order ランク上げ | シルバーからゴールドまで | 今週末
!review 5 | とても早かったです
!say みなさんこんにちは
!embed お知らせ | 本日は休業です | #ff8800
!send #お知らせ | 新しいサービスを始めました
```

## 準備（最初の1回だけ）

基本の作り方（Botの作成・BDFDへの登録・ホスティング）は [../README.md](../README.md) の手順1〜2・6と同じです。代行Botでは、次の点が違います。

### 1. Intentを2つオンにする
Developer Portal の Bot タブ → Privileged Gateway Intents で、
- **MESSAGE CONTENT INTENT** … `!` コマンドを使うために**必須**
- （入退室メッセージを使わないなら SERVER MEMBERS INTENT は不要）

オンにしたら、BDFDアプリの Settings → Gateway intents →「Sync intents with Developer Portal settings」をタップします。

### 2. 招待するときの権限
- チャンネルを見る / メッセージを送信 / 埋め込みリンク / メッセージ履歴を読む / ファイルを添付
- **チャンネルの管理**（チケットを作る・消すため）
- **ロールの管理**（チケットの閲覧権限を設定するため）
- **メッセージの管理**（`!say` などで元のコマンドを消すため）
- スコープで Slash commands（`applications.commands`）を有効に

> 「@everyone へのメンション」権限は付けないでください。発言代行で全員に通知が飛ぶのを防げます。

招待したら、サーバー設定 → ロールで **Botのロールをスタッフロールより上**に移動してください。

### 3. 変数を11個作る（Variables タブ）

| 変数名 | 初期値 | 用途 |
|---|---|---|
| `StaffRole` | （空） | スタッフのロールID |
| `TicketCat` | （空） | チケットを作るカテゴリID |
| `ResultCH` | （空） | 実績を投稿するチャンネルID |
| `OrderNo` | `0` | 注文番号 |
| `DoneCount` | `0` | 完了数 |
| `OpenTicket` | （空） | 開いているチケット（1人1つまで） |
| `Customer` | （空） | チケットの注文者 |
| `Service` | （空） | 注文されたサービス名 |
| `Staff` | （空） | 担当スタッフ |
| `Status` | （空） | 注文の状態 |
| `Rated` | （空） | レビュー済みか |

### 4. コマンドを作る
各ファイルのカードを1つずつ作ります。

- **トリガー欄**には `!order` のような **`!` 付きの名前**を入れます。
- 同じコマンドで **Slash command trigger** をオンにして、スラッシュの名前（`order` など）・説明・オプションを入れます。
  → これで `!order` と `/order` の**どちらでも同じコードが動きます**。
- `$onInteraction[...]` がトリガーのもの（ボタン・フォームの処理）は、スラッシュはオフのままです。

### 5. サーバーで設定する
1. スタッフ用のロールと、チケット用のカテゴリ（例: 「注文チケット」）、実績チャンネル（例: #実績）を作っておく
2. `/setup staff:@スタッフ category:注文チケット result:#実績`
3. 注文用チャンネルで `/panel`
4. `/menu` の料金は**見本**です。コードの `$addField[...]` を自分のサービスと価格に書き換えてください（`「料金表」ボタン` のコードも同じ内容なので両方とも直します）

## うまく動かないとき

| 症状 | 確認すること |
|---|---|
| `!` コマンドに反応しない | MESSAGE CONTENT INTENT が Developer Portal とアプリの両方でオンか |
| `/` コマンドが出ない | 最大1時間待つ / `applications.commands` 付きで招待したか |
| 「初期設定が終わっていません」 | `/setup` を実行したか |
| チケットが作られない | Botに「チャンネルの管理」「ロールの管理」権限があるか / カテゴリIDが正しいか |
| `/claim` で「スタッフ専用」と出る | `/setup` で設定したロールを、その人が持っているか |
| 実績が投稿されない | 実績チャンネルにBotの送信権限があるか |
| 「すでに注文チケットがあります」 | 前のチケットを `/close` で閉じる（手動で消した場合も、チャンネルが無ければ新しく作れます） |
| `/close` で返信が出ない | チャンネルごと削除するため、返信は表示されません（正常です） |

## 注意
- 代行サービスはゲームによっては利用規約で禁止されています。扱うサービスが規約に違反しないか、運営する前に確認してください。
- 支払いのやり取りはトラブルになりやすいので、料金・返金のルールを料金表やルールチャンネルにはっきり書いておくのがおすすめです。
